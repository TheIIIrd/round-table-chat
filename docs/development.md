# Разработка

## Структура

```
p2pchat/
  crypto/    primitives  noise  noise_xx  identity  sas
  net/       framing  link  tcp  discovery
  proto/     session  network  mesh  envelope  roster  trust  files  invite  events
  ui/        console  style
  bot/       runner  registry  commands
  games/     api  lobby  cards  connect_four  durak  mafia  hangman
  format.py  __main__.py
tests/       conftest + модули по слоям
tools/       local_testbed  run_tests_nopytest
docs/
```

Границы между слоями настоящие, а не декоративные:

- `crypto/` не знает о сети;
- `session.py` не знает о TCP — ему достаточно `Link`;
- `network.py` не знает о сообщениях — доставляет байты и решает, кого пускать;
- `mesh.py` не знает о соединениях — получает байты и отдаёт байты;
- игры не знают вообще ни о чём: возвращают намерения, а не отправляют.

Ломать эти границы не стоит. `Mesh` уже один раз перерос себя, держа всё сразу,
и это дало вполне конкретные ошибки: ограничение очереди в одном слое,
обойдённое в другом, и уборка передач, расползшаяся по трём методам.

## Тесты

```bash
python -m pytest tests -q                  # основной способ
python tools/run_tests_nopytest.py         # запасной, для машин без сети
```

Запасной раннер подменяет минимальный набор API pytest и дважды уже расходился с
ним в поведении: не поддерживал `pytest.raises(...) as`, а потом показывал в
прогоне печать из проверяемого кода, которую pytest прячет. **Если результаты
расходятся, прав pytest.**

Вывод перехватывается у каждого теста и показывается только при падении —
вместе с трейсбеком. Посторонняя печать в зелёном прогоне приучает пропускать
глазами то, на что стоило бы смотреть.

Тесты делятся на три сорта, и это деление осмысленное.

**Свойства.** Проверяют утверждение, а не строчку: Мэллори с двумя честными
хендшейками получает разные SAS; кадр из прошлой эпохи ключей не проходит.
Такие тесты переживают переписывание реализации.

**Сценарии.** Поднимают настоящие сокеты и проходят путь целиком — группа из
трёх, партия с ботом, передача файла.

**Генеративные** (`test_properties.py`). Разборщики обстреливаются мусором,
дурак играется тысячами случайных партий с проверкой инвариантов. Генератор
засеян, поэтому падение воспроизводится по номеру. Именно они нашли, что в
дураке не было отбоя, что карты ушедшего оставались «на руках» и что добор
возвращал карты выбывшему.

Переход на `hypothesis` был бы улучшением — он умеет сокращать контрпример, — но
заменяет, а не дополняет то, что есть.

## Инварианты, которые нельзя ломать молча

На каждый есть тест; если он упал, дело не в тесте.

| Инвариант                                                      | Что случится при нарушении                            |
|----------------------------------------------------------------|-------------------------------------------------------|
| Версия протокола поднимается при любом изменении формата       | Клиенты разных версий читают друг друга со сдвигом    |
| Таймаут отправки > таймаута ротации                            | Исправного пира отключит посреди штатной смены ключей |
| Кусок файла + заголовки ≤ полезной нагрузки сессии             | «Сообщение длиннее допустимого» во время передачи     |
| Заглушка в тестах не обещает того, чего нет в настоящем классе | Зелёные тесты при сломанном приложении                |
| Нет повторных определений функций в тестовом модуле            | Тихо запускается не тот код                           |
| Синонимы команд не смешивают алфавиты                          | Синоним работает только у того, кто повторит опечатку |
| Ссылки между документами ведут на существующие файлы           | Битая ссылка стоит читателю получаса                  |

## Линтер

```bash
pylint p2pchat tests tools demo_*.py
```

Настройки в `.pylintrc`, и **у каждого отступления написана причина**: молчаливо
отключённая проверка — это спрятанный долг, а не решённая проблема. Главное
послабление — `docstring-min-length = 12`: докстрока к трёхстрочной функции,
пересказывающая сигнатуру, делает код длиннее, а не понятнее.

## Стиль

Комментарий объясняет **почему**, а не что. «Проверяем владельца до снятия
записи» — плохо, это видно из кода. «Проверка до снятия: иначе чужое сообщение
выбьет передачу вместе с доступом к её временному файлу» — хорошо.

Особенно это касается мест, где решение выглядит странно. Такие места надо
защищать комментарием от «улучшения»: почему бикон не подписан, почему ротацию
инициирует только одна сторона, почему цвет не уходит в сеть.

## Что стоит сделать дальше

**Живой интероп с `snow` или `noise-c`.** Вектора подтвердили паттерн XX, но
кадрирование, привязка заголовка и ротация свежим DH — собственный протокол
поверх, и он ни с чем чужим не встречался. Это главный незакрытый пункт.

**Ограничения от вредного участника.** Нет предела на поток текста (лимит есть
только у бота на команды) и на число входящих соединений.

**Дополнение длины сообщений** против анализа трафика.

**UDP hole punching**: STUN, rendezvous, ARQ с учётом эпох ключей.

**Tor onion** — ещё одна реализация `Link`, снимает проброс портов,
динамические адреса и метаданные разом.

## Чего делать не стоит

- Возвращать проброшенные свойства в `Mesh` ради удобства — они размывают
  границу, которую разделение слоёв провело.
- Отправлять ANSI по сети. Цвет накладывается локально; иначе один участник
  сможет управлять терминалом другого.
- Добавлять поля в конверт «на будущее». Поле, которое никто не читает, хуже
  отсутствующего: оно создаёт впечатление, что что-то обеспечено.
- Расширять пределы в `.pylintrc` вместо разбиения кода.
