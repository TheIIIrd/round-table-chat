# Если что-то не работает

Собрано из реальных случаев, а не придумано. Каждый раздел начинается с
симптома.

## Участники не видят друг друга

Проверяйте по порядку, не перескакивая.

**1. Прошло ли достаточно времени?** Группа собирается не мгновенно:
расшифровка каждого ключа занимает около двух секунд (Argon2id, 256 МиБ), а
несколько клиентов, запущенных разом, делят один процессор. Четыре процесса —
до десяти секунд. Это цена стойкости пассфразы к перебору, а не тормоза сети.
Дождитесь, пока `/peers` покажет всех.

**2. Одинаковый ли у всех ростер?**

```bash
python -m p2pchat roster show
```

Сравните **идентификатор группы** — он должен совпасть у всех до символа. Он
входит в хендшейк, поэтому при расхождении соединения не будет вообще.
Отличается — у кого-то старый файл; раздайте свежий через `invite --group`.

**3. Есть ли в группе хоть кто-то с доступным адресом?** Соединение
устанавливает тот, чей публичный ключ меньше, но дозвониться нужно хотя бы до
одного. Если все за NAT без проброса — не соединится никто.

**4. Открыт ли порт снаружи?** С другой машины:

```bash
nc -vz 203.0.113.10 9333
```

Не отвечает — проброс на роутере не сделан или сделан не на тот внутренний
адрес. Слушать нужно на `0.0.0.0`, а не на конкретном интерфейсе.

**5. Попробуйте вручную:** `/connect host:port`. Соединилось — значит проблема в
адресе из ростера; он запомнится, и дальше будет работать само.

## Двое на одной машине не видят друг друга, а с остальными всё хорошо

Классика, и не ваша вина. Ростер один, значит адрес в нём внешний. Двое за одним
NAT по внешнему адресу друг друга обычно не достают: пакет уходит на роутер и
возвращается, только если тот умеет hairpin NAT.

Решения: `--discover lan`, либо один раз `/connect 127.0.0.1:9334`. Подробно — в
[connecting.md](connecting.md), сценарий 3.

## Обнаружение в сети молчит

Сначала проверьте, работает ли мультикаст у вас вообще:

```bash
python -m p2pchat lantest
```

Команда поднимает два узла обнаружения в одном процессе и смотрит, увидят ли
они друг друга. Если да — `--discover lan` можно пользоваться, и дело в
чём-то другом. Если нет, команда подскажет, что посмотреть:

```bash
ip link | grep -i multicast        # есть ли у интерфейсов флаг MULTICAST
ip route show type multicast       # есть ли маршрут для 224.0.0.0/4
sudo iptables -L INPUT -n          # не режется ли UDP
```

Мультикаст доступен не везде: в контейнерах, при некоторых настройках firewall
и в сетях без маршрута для `239.0.0.0/8` сокет создаётся успешно, а пакеты
никуда не уходят. Бикон отправляется дважды — через маршрут по умолчанию и явно
через loopback, — поэтому участники **на одной машине** находят друг друга даже
там, где обычный маршрут сломан.

Ещё проверьте, что все в одном сегменте сети: TTL бикона равен единице, через
маршрутизатор он не пройдёт.

Чат от неработающего обнаружения не ломается — просто указывайте адреса в
ростере или подключайтесь через `/connect`.

## Вместо цвета видны `?[38;5;114m`

Это `prompt_toolkit`: его `patch_stdout()` заменяет `\x1b` на `?`, чтобы
печатаемый текст не управлял терминалом, и под замену попадают наши коды.

```bash
python -m p2pchat colortest
```

Команда печатает образцы всех стилей мимо `prompt_toolkit`. Если там цвет есть,
а в чате нет — диагноз подтверждён. Запускайте чат с `--plain`: простой ввод без
библиотеки. Цена — строка ввода будет рваться приходящими сообщениями.

## Цвета нет вообще

Причины по убыванию частоты: вывод идёт не в терминал (пайп, файл); переменная
`NO_COLOR`; `TERM=dumb`; флаг `--no-color`. `colortest` покажет, что именно
сработало.

На Windows 10+ разбор ANSI включается автоматически.

## `unrecognized arguments: --no-color`

Так было раньше: argparse требовал ставить общие флаги до подкоманды. Сейчас
работают оба порядка. Если ошибка появилась — у вас старая версия.

## «Под этим ником известен другой ключ»

Соединение отвергнуто, и это правильное поведение. Либо собеседник переустановил
чат, либо кто-то выдаёт себя за него.

**Свяжитесь с человеком по другому каналу.** Подтверждает — `/forget <ник>`,
затем сверьте новый отпечаток голосом. Не подтверждает — не соединяйтесь.

## Файл не передаётся

- **«файл больше лимита»** — предел 64 МиБ, проверяется с обеих сторон.
- **«пустой файл отправлять нечего»** — так и есть.
- **«не удалось начать приём»** — каталог `~/.p2pchat/downloads` недоступен: нет
  прав, кончилось место или на его месте файл.
- **«хеш не совпал»** — файл повреждён по дороге; ничего в каталог не попадёт.
- **`/accept` говорит «укажите идентификатор»** — так и задумано: пустая строка
  совпала бы с первым попавшимся предложением, и вы приняли бы не тот файл.
- **«подходит несколько»** — введите больше символов идентификатора.
- **«ещё не ответил на предыдущие предложения»** — не больше трёх висящих
  предложений одному человеку; подождите или попросите его ответить.

## Партия зависла

На ход есть таймаут: в «четыре в ряд» две минуты, в дураке три, в мафии от двух
до четырёх в зависимости от фазы. Ушедший участник партию не вешает — она
завершается или продолжается без него.

Прервать вручную: `!stop` (может любой участник партии).

## Забыл пассфразу

Восстановить нельзя. Ключ зашифрован Argon2id, и это не формальность. Придётся
создать новый и пройти процедуру смены ключа из [security.md](security.md).

## Диагностика: что смотреть

```bash
python -m p2pchat whoami          # свой ключ и отпечаток
python -m p2pchat roster show     # состав и идентификатор группы
python -m p2pchat colortest       # что видит терминал
```

В чате: `/peers` (кто на связи), `/fingerprint` (свой отпечаток).

Файлы состояния в `~/.p2pchat` (или в `--home`):

| Файл               | Что внутри                                          |
|--------------------|-----------------------------------------------------|
| `id.key`           | приватный ключ под пассфразой, права `0600`         |
| `roster.json`      | состав группы                                       |
| `known_peers.json` | известные ключи, отметки о сверке, последние адреса |
| `downloads/`       | принятые файлы                                      |

Переписка **не сохраняется** нигде: история живёт только в памяти процесса.
