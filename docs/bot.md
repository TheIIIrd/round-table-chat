# Бот

Бот — **обычный участник меша**, а не отдельная сущность. У него своя пара
ключей, своя запись в ростере, свой порт, и остальные видят его как участника с
пометкой «бот». Отдельной криптографии у него нет.

## Запуск

```bash
python -m p2pchat --home ~/.p2pchat/dice keygen --nick dice
python -m p2pchat --home ~/.p2pchat/dice bot --nick dice --listen 0.0.0.0:9334
```

Ключ бота должен быть в ростере с флагом `"bot": true`:

```bash
python -m p2pchat roster add dice 4f21a9… --address 203.0.113.10:9334 --bot
```

Флаг не даёт боту прав — он нужен, чтобы клиенты рисовали его реплики иначе и
чтобы боты не разговаривали друг с другом.

## Ключ бота: осознанный выбор

Бот работает без человека, значит пассфразу нужно откуда-то взять. Вариантов
два, и оба с недостатком.

**Пассфраза вручную при каждом запуске.** Безопаснее, но автоперезапуск
невозможен: после перезагрузки машины бот не поднимется сам.

**Пассфраза из окружения** (`--key-from-env`, переменная `P2PCHAT_PASSPHRASE`).
Автоперезапуск работает, но **компрометация хоста бота означает чтение всей
переписки группы** — бот полноценный участник меша и видит всё.

Отсюда практический совет: держите бота на машине, которой доверяете так же,
как своей, и не считайте её «просто сервером для кубика».

## Команды

| Команда                    | Что делает         |
|----------------------------|--------------------|
| `!roll d20`, `!roll 3d6+2` | бросок кубиков     |
| `!coin`                    | монета             |
| `!choose пицца, суши`      | выбор из вариантов |
| `!help`                    | список команд      |

Игровые команды — в [games.md](games.md).

Русские синонимы работают везде: `!бросок`, `!монета`, `!выбери`, `!помощь`.
В подсказках их нет намеренно — перечислять по два имени на команду значит
удвоить справку ради тех, кто и так угадает.

## Чего бот не делает

- **Не принимает файлы.** Любое предложение отклоняется автоматически.
- **Не отвечает другим ботам.** Иначе два бота уйдут в бесконечную переписку.
- **Не выполняет ничего, кроме зарегистрированных команд.** Ни файловой
  системы, ни сети у обработчиков нет — им передают только распарсенные
  аргументы и ник отправителя.
- **Не реагирует на флуд.** Token bucket: пять команд подряд, дальше по одной
  каждые две секунды. Лишнее отбрасывается молча — ответ на флуд это тоже флуд.

## Про честность кубика

Случайность берётся из `secrets`, а не из `random`: последний —
детерминированный Mersenne Twister, по нескольким результатам его состояние
восстанавливается.

Но криптографически это ничего не доказывает: **тот, кто держит хост бота,
видит результат до отправки** и технически может его подменить. Для игры с
друзьями это приемлемо, если проговорено вслух. Если бросок реально что-то
решает между не доверяющими друг другу людьми, нужна совместная генерация с
коммитами — каждый присылает хеш своего случайного значения, потом все
раскрывают, результат складывается по XOR. Такого режима здесь нет.

То же касается карточных игр: владелец узла с ботом видит все руки. Разумнее
всего, чтобы держатель бота в партии не участвовал.

## Своя команда

```python
@registry.command(
    "погода",
    pattern=r"([\w\- ]{1,40})",
    summary="сообщить погоду в городе",
    aliases=("weather",),
)
def weather(ctx, city):
    return f"{ctx.nick}: в городе {city} сейчас неизвестно что"
```

Правила, которые каркас обеспечивает за вас: команда обязана начинаться с
префикса и совпасть с якорным регулярным выражением целиком; длина ввода
ограничена до разбора; на отправителя действует ограничитель частоты; у
обработчика есть таймаут; исключение внутри обработчика превращается в одну
строку в чате, а не роняет бота вместе с текущей партией.

Чего каркас не сделает: не проверит вашу логику. Не зовите `eval`, не
пробрасывайте строки в shell, не открывайте файлы по имени из аргумента.

## Ограничения

Один бот на группу поддерживает одну активную партию за раз. Несколько ботов в
одном ростере работать будут, но между собой они не разговаривают, и каждый
ведёт свои партии независимо — общего состояния у них нет.
