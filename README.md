# p2pchat

Безопасный консольный P2P-чат: попарные каналы Noise, групповой меш, передача
файлов и бот. Без сервера, без учётных записей, без хранения переписки.

```
Noise_XX_25519_ChaChaPoly_BLAKE2s   хендшейк со скрытием идентичности
ротация ключей свежим DH            forward + post-compromise secrecy
попарный меш до 8 участников        никаких общих групповых ключей
сверка SAS голосом                  защита от активного MITM
```

## Установка

```bash
pip install cryptography          # обязательная зависимость, одна
pip install prompt_toolkit        # необязательно: строка ввода не рвётся
```

## Пять минут до первого сообщения

**1. Каждый создаёт себе ключ.**

```bash
python -m p2pchat keygen --nick alice
# Отпечаток: 5117 5800 47c1 1ebf 7a24 5ba1 155d d988
# Публичный: 271d1e14714c23490b74f935db4714e59fd52e98bbf0b2b5e31712411a62db76
```

Ключ ложится в `~/.p2pchat/id.key` под пассфразой. Публичный ключ передаётся
остальным — он открытый, его можно слать хоть в мессенджере.

**2. Каждый показывает свою строку-приглашение.**

```bash
python -m p2pchat invite --address 203.0.113.10:9333
# p2pchat:KAZFASIBHHWPYKLCKHX74IFFXIJZHAMYSRZB6QFUKNEPH25FMMN6S23WN5MAAJDVBQZ…
# Отпечаток: 1047 9d0a 4c43 4510 5222 071e 2338 40f1
```

Одна строка вместо копирования ключа и правки JSON. Тот, кто собирает группу,
принимает приглашения остальных, а затем раздаёт готовый ростер одним куском:

```bash
python -m p2pchat roster new друзья
python -m p2pchat roster add-invite p2pchat:KAZFASIB…       # и так каждого
python -m p2pchat invite --group                            # отдать всем
python -m p2pchat roster add-invite p2pchat-group:KAZFARYB… # принять у себя
```

Приглашение несёт публичный ключ. Если оно шло через канал, который
контролирует противник, ключ подменяется — поэтому команды печатают отпечаток,
и его всё равно нужно сверить голосом. Ручной путь никуда не делся:
`roster add <ник> <ключ> --address host:port`.

Файл `~/.p2pchat/roster.json` должен быть одинаковым у всех: идентификатор
группы считается из ключей участников и входит в хендшейк.

**3. Все запускают чат.**

```bash
python -m p2pchat chat --listen 0.0.0.0:9333
python -m p2pchat chat --listen 0.0.0.0:9333 --discover lan   # в одной сети
```

С `--discover lan` адреса в ростере не нужны вовсе: участники находят друг
друга мультикастом. Мультикаст доступен не везде — в контейнерах и при
некоторых настройках firewall сокет создаётся, а пакеты никуда не уходят.
Программа один раз скажет об этом прямо в чат и продолжит работать по адресам
из ростера; для нескольких клиентов на одной машине есть запасной путь через
loopback. Бикон не подписан — и не должен быть: ключи зафиксированы
в ростере, поэтому подложный адрес даёт ровно одно последствие, неудачную
попытку соединиться. Взамен в пределах сегмента видно, что участник с таким-то
ключом здесь присутствует, — поэтому флаг, а не поведение по умолчанию.

**4. Сверяют SAS.** При соединении обе стороны видят одинаковый код из
тридцати цифр. Прочитайте его собеседнику голосом; если совпал — `/verify bob`.
Пока код не сверен, каждое сообщение помечается `!`.

Разговор один на один без ростера:

```bash
python -m p2pchat chat --direct 198.51.100.7:9333
```

Бот (на любой машине из ростера):

```bash
python -m p2pchat bot --nick dice --listen 0.0.0.0:9334
```

## Локальный стенд

Несколько участников на одной машине — обычный сценарий для проверок. Каждому
нужен свой каталог и свой порт; программа не знает, что соседи рядом, и ходит
через настоящие сокеты на 127.0.0.1.

```bash
python tools/local_testbed.py --reset      # alice, bob, carol и бот dice
python tools/local_testbed.py --tmux       # то же, сразу в панелях tmux
python tools/local_testbed.py --users петя,вася --no-bot
```

Скрипт создаёт ключи, раскладывает одинаковый ростер и печатает готовые
команды запуска — по одной на терминал. Для проверки обнаружения добавьте
`--discover lan` к командам: на одной машине мультикаст ходит через loopback. Пассфраза у стенда одна и известная:
это допустимо для песочницы на localhost и больше нигде.

Группа собирается не мгновенно. Расшифровка ключа занимает около двух секунд
(Argon2id, 256 МиБ), а четыре клиента, запущенные разом, делят один процессор —
итого до десяти секунд до полного меша. Это стоимость стойкости пассфразы к
перебору, а не тормоза сети. Дождитесь, пока `/peers` покажет всех.

## Команды в чате

| Команда                          | Что делает                                       |
|----------------------------------|--------------------------------------------------|
| `/peers`                         | кто на связи                                     |
| `/verify <ник>`                  | отметить, что SAS сверен голосом                 |
| `/forget <ник>`                  | забыть ключ, если собеседник переустановил чат   |
| `/send <ник> <путь>`             | предложить файл                                  |
| `/accept <id>`, `/decline <id>`  | ответ на предложение файла                       |
| `/w <ник> <текст>`               | сказать лично (ночные ходы в играх — только так) |
| `/connect host:port`             | подключиться вручную                             |
| `/fingerprint`, `/help`, `/quit` | остальное                                        |

### Русские названия команд

Все команды — и в чате, и у бота, и в играх — понимают русские синонимы.
В подсказках их нет намеренно: перечислять по два имени на команду значит
удвоить справку ради тех, кто и так угадает. Полный список здесь.

| Чат                                                                                                                                                                                                                        | Бот и лобби                                                                                                                                                                  | Игры                                                                                                                                                                                                                                                                                                                           |
|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `/кто` → peers, `/сверить` → verify, `/забыть` → forget, `/подключить` → connect, `/файл` → send, `/принять` → accept, `/отклонить` → decline, `/лично` → w, `/отпечаток` → fingerprint, `/помощь` → help, `/выход` → quit | `!игра` → game, `!войти` → join, `!выйти` → leave, `!начать` → start, `!стоп` → stop, `!кто` → who, `!бросок` → roll, `!монета` → coin, `!выбери` → choose, `!помощь` → help | Названия: `дурак` → durak, `мафия` → mafia, `виселица` → hangman, `четыре` → c4.<br>Ходы: `!ход` → attack/drop, `!подкинуть` → add, `!бить` → beat, `!взять` → take, `!пас` → pass, `!рука` → hand, `!стол` → table, `!убить` → kill, `!проверить` → check, `!голос` → vote, `!день` → day, `!буква` → letter, `!слово` → word |

Бот отвечает на `!roll d20`, `!roll 3d6+2`, `!coin`, `!choose а, б, в`, `!help`.

## Игры

```
!game            список игр
!game c4         собрать партию
!join / !leave   записаться или выйти
!start / !stop   начать или прервать
!who             кто играет
```

| Игра                 | Кого зовём | Команды                                                                        |
|----------------------|------------|--------------------------------------------------------------------------------|
| `c4` — Четыре в ряд  | 2          | `!drop 4`, `!board`                                                            |
| `durak` — подкидной  | 2–6        | `!attack`, `!add`, `!beat <своя> <чужая>`, `!take`, `!pass`, `!hand`, `!table` |
| `mafia`              | 4–8        | `!kill`, `!check`, `!day`, `!vote`, `!status`                                  |
| `hangman` — виселица | 1–8        | `!letter а`, `!word ответ`, `!gallows`                                         |

Бот ведёт партию: следит за очередью, засекает время на ход, раздаёт приватное
состояние. Если игрок отвалился и вернулся, ему заново уходит его положение в
игре; если не вернулся — партия завершается, а не висит.

**Ночные ходы и карты — только лично боту.** Всё, что написано в общий чат,
видят все, поэтому в консоли есть `/w <ник бота> !убить вася`. Мафия
предупреждает об этом при раздаче ролей, но подстраховать за игрока не может.

Каждая игра проверяет каркас со своей стороны: «Четыре в ряд» — строгую
очерёдность, дурак — приватные руки и сложное состояние, мафия — фазы, роли и
голосование, виселица — игру вообще без очереди.

Ввод в дураке снисходителен к человеку: масть можно назвать как угодно
(`6т`, `6к`, `6c`, `6♣`), латинские `p` и `B` понимаются как `п` и `В`, а если
достоинство в руке одно — масть не нужна вовсе (`!attack 10`). Несколько карт
кладутся одной командой: `!attack 6♥ 6♣`. Под столом бот показывает, что каждый
может сделать прямо сейчас.

В дураке взят устоявшийся объём правил: 36 карт, козырь по нижней карте,
подкидывает любой картой того же достоинства, добор до шести, последний с
картами — дурак. Перевод и «погоны» не реализованы сознательно: они меняют
очерёдность и в разных компаниях трактуются по-разному, а половинчатая
реализация спорных правил хуже их отсутствия.

### Как добавить свою игру

Игра не имеет доступа к сети. Она получает событие и возвращает список
намерений — `Say` всем, `Whisper` лично, `Finish` в конце. Превращает намерения
в сообщения хозяин партии. Поэтому правила тестируются целиком без сокетов, а
таймауты, лимиты и изоляция живут в одном месте и не дублируются.

```python
class MyGame:
    name, title = "mygame", "Моя игра"
    min_players, max_players = 2, 4
    verbs = frozenset({"move"})

    def __init__(self, rng): ...                    # случайность снаружи — ради тестов
    def start(self, players) -> list[Action]: ...
    def handle(self, player, verb, rest) -> list[Action]: ...
    def on_leave(self, player) -> list[Action]: ...
    def tick(self, now) -> list[Action]: ...        # таймауты хода
    def snapshot_for(self, player) -> str: ...      # вернулся после обрыва
```

Три шага: файл в `p2pchat/games/`, строка в `CATALOG`, тест на правила. Ни
бота, ни меша, ни ключей трогать не нужно.

Приватная раздача (руки в карточных играх, роли в мафии) достаётся бесплатно:
меш попарный, поэтому `Whisper` — это просто отправка в личную сессию игрока,
сквозь то же шифрование. **Но** тот, кто держит хост бота, технически видит всё
скрытое состояние. Для дурака или покера это надо проговаривать участникам
вслух; по-настоящему решает задачу только mental poker, которого здесь нет.

## Как это устроено

| Слой         | Файлы                                                               | Ответственность                              |
|--------------|---------------------------------------------------------------------|----------------------------------------------|
| Примитивы    | `crypto/primitives.py`                                              | X25519, ChaCha20-Poly1305, BLAKE2s, HKDF     |
| Noise        | `crypto/noise.py`, `crypto/noise_xx.py`                             | состояния шифра, паттерн XX                  |
| Идентичность | `crypto/identity.py`, `crypto/sas.py`                               | ключ под Argon2id, отпечаток, SAS            |
| Транспорт    | `net/framing.py`, `net/link.py`, `net/tcp.py`                       | кадры, абстракция канала, TCP                |
| Сессия       | `proto/session.py`                                                  | хендшейк, привязка заголовка, ротация ключей |
| Приложение   | `proto/mesh.py`, `envelope.py`, `roster.py`, `trust.py`, `files.py` | меш, конверты, группа, доверие, файлы        |
| Интерфейсы   | `ui/console.py`, `bot/`                                             | чат и бот поверх одного и того же меша       |
| Игры         | `games/api.py`, `lobby.py`, `cards.py`                              | контракт игры, лобби и таймауты, колода      |
| -            | `connect_four.py`, `durak.py`, `mafia.py`, `hangman.py`             | сами игры                                    |

Ключевые решения:

- **Попарный меш.** Групповое сообщение шифруется отдельно для каждого. Трафик
  растёт линейно, зато нет общих групповых ключей, которые пришлось бы менять
  при уходе участника. Отсюда потолок в 8 человек.
- **Идентификатор группы = BLAKE2b от отсортированных ключей.** Каждый считает
  его сам, любая правка состава его меняет, а он входит в prologue хендшейка —
  значит расхождение в составе обнаруживается при соединении, а не после.
- **Ротацию инициирует только тот, кто начинал хендшейк.** Иначе одновременный
  запуск с двух сторон дал бы два разных набора ключей. Второй стороне остаётся
  послать запрос.
- **Кто кому звонит:** тот, чей публичный ключ меньше. Договариваться не нужно,
  и не возникает двух сессий на пару.
- **Адрес — подсказка, а не удостоверение.** Обнаружение в сети, запомненный
  адрес и оповещение о смене порта не участвуют в аутентификации: ключи
  пинятся ростером. Поэтому упрощать поиск друг друга можно свободно, а вот
  обмен ключами — нет.
- **Бот — обычный участник меша.** Отдельной криптографии у него нет. Он не
  принимает файлы, не отвечает другим ботам и выполняет только
  зарегистрированные команды под ограничителем частоты.

## Оформление вывода

Два разных механизма, которые важно не смешивать.

**Структура едет по проводу.** Доски, расклады и карточки ролей бот заключает в
рамки из псевдографики прямо в тексте сообщения. Их видят все одинаково,
независимо от терминала, и они остаются читаемыми там, где цвета нет вовсе.

**Цвет накладывается локально.** ANSI-последовательности никогда не уходят в
сеть: сообщение остаётся обычным текстом, а раскрашивает его клиент получателя.
Реплики бота идут с полосой `┃`, ники окрашены по своему **публичному ключу**
(а не по имени — подделать чужой цвет, назвавшись его ником, не выйдет),
предупреждения красные, служебные строки приглушены. Несверенный собеседник
помечается `?` перед ником — и это видно даже в чёрно-белом терминале.

Отключить цвет: `--no-color`, переменная `NO_COLOR` или `TERM=dumb`. Вывод не в
терминал (пайп, файл) тоже отключает его сам.

Проверить, что видит именно ваш терминал:

```bash
python -m p2pchat colortest
```

Команда печатает образцы всех стилей и подсказывает, почему цвета может не
быть. Если вместо цвета видны последовательности вида `?[38;5;114m`, дело в
`prompt_toolkit`: его `patch_stdout()` заменяет `\x1b` на `?`, чтобы печатаемый
текст не управлял терминалом, и под замену попадают наши коды. Цвет отдаётся
через `print_formatted_text(ANSI(...))` именно поэтому. Если библиотека всё
равно ведёт себя странно, `--plain` включает простой ввод без неё: строка ввода
будет рваться приходящими сообщениями, но цвет заработает.

На Windows 10+ разбор ANSI включается автоматически (`ENABLE_VIRTUAL_TERMINAL_PROCESSING`).

Отдельно: весь входящий текст проходит очистку от управляющих символов. Без неё
любой участник мог бы прислать `\x1b[2J` и очистить вам экран, переставить
курсор или подменить заголовок окна.

## Модель угроз

Защищаемся от: пассивного прослушивания; активного MITM (при условии сверки
SAS); компрометации ключа задним числом; компрометации ключа посреди сессии
(после ближайшей ротации); доступа к выключенному диску; злонамеренного
участника, пытающегося прислать вредное имя файла или зафлудить бота.

**Не** защищаемся от: скомпрометированной машины (кейлоггер, доступ к памяти);
анализа трафика — длины сообщений видны наблюдателю как есть; недоступности
пира; человека, который не сверил SAS.

## Что честно знать перед использованием

1. **Самописная реализация Noise без аудита.** Для дружеского круга — нормально.
   Для тех, кому угрожает целевая атака, — нет; там Signal.
2. **Ключи в памяти Python затереть нельзя.** `bytes` неизменяемы, GC копирует
   объекты, страница уходит в swap. Хранилище защищает выключенный диск.
3. **Ключ бота.** Бот работает без человека. Либо пассфраза вводится вручную при
   каждом запуске (нет автоперезапуска), либо берётся из окружения
   (`--key-from-env`) — и тогда компрометация хоста бота означает чтение всей
   переписки группы, ведь бот полноценный участник меша.
4. **Кубик бота не является доказуемо честным.** `secrets` даёт качественную
   случайность, но владелец хоста видит результат до отправки. Для ставок нужна
   совместная генерация с коммитами — её здесь нет.
5. **Метаданные видны.** Прямой TCP означает, что наблюдатель видит, кто с кем
   соединяется. Tor onion или UDP с обходом NAT — следующий этап.

## Линтер

```bash
pylint p2pchat tests tools demo_*.py
```

Настройки в `.pylintrc`, и у каждого отступления от умолчаний написана причина:
молчаливо отключённая проверка — это спрятанный долг, а не решённая проблема.
Главное послабление — `docstring-min-length = 12`: докстрока к трёхстрочной
функции, пересказывающая её сигнатуру, делает код длиннее, а не понятнее.

Что там честно записано как долг: у `Mesh` восемнадцать полей — он держит
соединения, доверие, обнаружение, файлы и часы разом. Предел поднят, но однажды
класс стоит разделить на транспортную и прикладную половины.

## Тесты

```bash
python -m pytest tests -q          # обычный способ
python run_tests_standalone.py     # если pytest недоступен
```

Хендшейк проверен на официальных векторах Noise: реализация побайтово совпала
с чужой, посчитанной независимо. Это то, чего самопроверка дать не может —
одинаковая ошибка с обеих сторон в ней незаметна. Вектора не входят в
репозиторий (см. `tests/test_vectors.py`), поэтому на свежей копии тест
пропускается, пока их не скачать:

```bash
mkdir -p tests/vectors && curl -L -o tests/vectors/cacophony.json https://raw.githubusercontent.com/mcginty/snow/master/tests/vectors/cacophony.txt
```

Всего 205 тестов. Содержательные из них: MITM с двумя честными хендшейками даёт
сторонам разные SAS; подделанный кадр, повтор и подмена типа сообщения
отвергаются; потеря сообщения обнаруживается; кадр из прошлой эпохи ключей не
проходит после ротации; ключ вне ростера не пускается в группу; `../../.ssh/…`
не превращается в путь; файл с неверным хешем не появляется в каталоге;
ограничитель частоты гасит флуд на бота; несверенный собеседник помечается в
каждой строке; опечатка в любом символе приглашения ловится контрольной суммой
и проверкой каноничности base32; бикон из чужой группы игнорируется; партия
не зависает при уходе игрока и завершается по таймауту хода; вернувшийся
игрок получает своё состояние обратно; козырная шестёрка бьёт некозырного туза;
партия в дурака двух автоигроков доходит до конца без зависаний; роль в мафии не
утекает в общий канал, а мафия знает своих; каждая подкоманда CLI разбирается,
и любое обращение обработчика к несуществующему аргументу — провал теста;
чужое сообщение с ANSI-последовательностями не управляет терминалом; закрытие
лишнего соединения при гонке дозвонов не выносит живое; общие флаги работают и
до подкоманды, и после; пометки в чате читаются при включённом цвете, а не
только в конвейере. Часть тестов поднимает настоящие сокеты и проходит весь путь
целиком — включая группу из трёх участников и бота.

## Что дальше

- Живой интероп: провести хендшейк с работающим `snow` или `noise-c`, а не
  только совпасть с их векторами
- Фаззинг разборщиков (`hypothesis`) — всего, что читает байты из сети
- Дополнение длины сообщений против анализа трафика
- UDP hole punching: STUN, rendezvous, ARQ с учётом эпох ключей
- Автоматический проброс порта (UPnP/NAT-PMP) отдельным флагом
- Жизненный цикл долговременных ключей: ротация, отзыв, резервная копия
